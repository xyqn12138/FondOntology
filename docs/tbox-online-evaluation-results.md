# T-BOX 在线评测与深层迭代

评测日：2026-10-08（America/Los_Angeles）；运行日志为 2026-10-09 UTC。
本轮只发送本体 schema 与冻结问题，不发送实例图、实际基金信息或密钥。

## 结论

确定性覆盖改善明显，但在线计划生成仍有缺陷：

- 相对上一轮 `final`，800 字符严格上下文覆盖从 36/44 提升到 44/44。
- 10000 / 1800 字符从 39/44 提升到 44/44，独立契约保持 23/23。
- 11 题在线小批，上一轮 `final` 联合通过 3/11，当前版本 5/11。
- 独立裁判的已知正误校准只有 3/5。在线分数仅作诊断，不能视为可靠准确率。
- 不改正式本体、不加载 A-BOX、不接入生产自修复、不提交或推送。

44/44 是公开冻结集上的 T-BOX 文本覆盖，不是最终问答正确率、任意 OWL
语义保持率或盲测成绩。小批刻意包含已有失败题，不能外推总体性能。

## 协议

解析模型：`qwen3.8-flash`，裁判：`deepseek-v3.2`。实际响应 model 与请求一致。
均使用项目配置的阿里 MaaS OpenAI-compatible endpoint；运行时查询 `/models`
确认名称可用，不据模型名猜测服务端部署版本。

新增工具 `tools/tbox_online_bench.py`，在线调用显式 opt-in，与单元测试隔离。

1. 校验两份冻结 fixture SHA256 和全部本体 TTL hash，禁止换 gold 或本体后仍比较历史结果。
2. 同题分别注入 full、历史 baseline、历史 final、当前实现上下文。
3. baseline/final 使用修改前已保存的渲染文本，不事后模拟旧实现。
4. 主实验统一 800 字符切片预算；full 为 18103 字符语义视图。
5. 主实验没有向解析模型提供 gold；裁判得到原题、full 视图、冻结覆盖参考和计划。
6. 确定性检查概念白名单、视图内定义、字段 domain、路径连续性和方向、冻结 gold 覆盖。
7. 独立裁判检查问题的投影、条件、时间、排序、聚合与拒答语义。
8. 同时满足解析成功、结构合法、gold 覆盖和裁判认可，才记为“联合通过”。

采用固定 seed=17 的对照呈现顺序，temperature=0，无实际采样 seed 保证。
独立请求不存在同屏排序竞争；这不消除模型随机性或裁判偏差。
流式请求，读超时 90 秒，最多尝试两次；主模型响应上限 1800 tokens，
裁判 1300 tokens。本轮保存响应未出现 API 失败、超时或重试。
设置 `--max-calls` 控制逻辑模型调用数，不等同 HTTP 尝试次数。
未获取计费单，不报告费用金额。

响应缓存按 prompt/model/endpoint/输出上限/temperature 的 hash 区分。
缓存命中只复用同条件结果，不是新模型采样，不能据重复运行声称模型稳定。
每次请求保存 prompt、JSON、原文、响应 model、token usage、耗时和失败类型；
不保存鉴权头或含密钥的异常内容。

### 与生产协议的区别

这里使用扩展语义 IR，支持 `projections / temporal / computed / paths`。
生产 `_LLM_SCHEMA` 尚不能完整表达这些字段；生产解析器还有确定性兜底。
本实验不经过兜底、不执行 SPARQL，不代表生产 QA 端到端准确率。
“full”也是 `render_for_llm()` 的完整语义视图，不是全部 OWL TTL 公理；
缺少定义、复杂 restriction 等内容，不能称作无信息损失的金标准。

## 确定性迭代

本轮修改限于 `schema_retriever.py`：

- 通用“收费/费用”对称归一化，不增加整句到 IRI 的答案表。
- 泛化字段词仅在已识别领域内扩展，避免“金额”全局召回所有金额属性。
- 时间表达沿已命中字段 domain 与类祖先召回 date/dateTime 字段。
- 明确命中的父类不强制所有弱匹配子类进入必需包。
- 提及容器与子对象时补直接桥，不受已有标量字段命中的干扰。
- 每个属性包保留自身 domain/range、路径支撑，不再捎上全部候选类。
- 明确命中两端类的对象属性优先，防止连接被弱字段挤掉。
- “基金 + 业务对象”在本体有直接连接时保留 Fund，未硬编码 fee/portfolio IRI。

这些规则仍有局限：时间需求可能召回同域多个日期，泛化金额可能产生噪声；
弱匹配得到的错误 domain 仍可能扩大候选。没有任意自然语言依赖完备性保证。

| 轮次 | 10000 覆盖 | 1800 覆盖 | 800 覆盖 | 契约 |
|---|---:|---:|---:|---:|
| 上一轮 final | 39/44 | 39/44 | 36/44 | 23/23 |
| online iteration1 | 36/44 | 36/44 | 36/44 | 22/23 |
| online iteration2 | 43/44 | 43/44 | 42/44 | 23/23 |
| online iteration3 | 44/44 | 44/44 | 43/44 | 23/23 |
| online final | 44/44 | 44/44 | 44/44 | 23/23 |

第一轮过滤过强丢失主题跨节点属性，完整保存退化。第二/三轮 H12 小预算
连接退化通过通用桥优先级恢复。最终相对旧 final 无严格覆盖退化题。
平均字符为 788.8 / 774.3 / 571.5，核心精度代理约 64.5% / 64.7% / 69.5%：
覆盖改善伴随额外支撑内容，不声称消除了所有噪声。

## 自修复实验

`--repair` 仅用于评测器。给模型原题、同一 T-BOX、初次计划与确定性结构错误；
不给 gold、裁判评分、缺失 gold 字段或参考答案。进行一次修复后再次校验。

该实验针对中间 iteration2 上下文，不是最终代码版本。
联合通过 5/11 -> 6/11，新增主要来自 H16；D03 的 null 占位被修正，
但 D11 的派生计算虽然开始表达，仍出现非法字段。
其中裁判对 H16 的判断本身不稳定，因此不据这一个样本宣布修复有效。
生产未接入此路径，也未改变证据引用闸门。

## 裁判校准

用另一个合成设备 schema 构造 5 个已知正误计划，未使用基金题答案：

| 控制 | 应认可 | 裁判认可 | 是否正确 |
|---|---|---|---|
| 子类继承 range + 合法反向路径 | 是 | 是 | 是 |
| 错误路径方向 | 否 | 是 | 否 |
| 缺少时间限定 | 否 | 否 | 是 |
| 无上文含糊需求并请求澄清 | 是 | 否 | 否 |
| 未定义属性 | 否 | 否 | 是 |

裁判只答对 3/5，不能作为唯一质量门禁。本轮没有为了提升在线分数，
反复换裁判或修改冻结 gold。校准原始响应单独保存。
后续应先建立更大的正误控制集、独立专家复核及裁判一致性，再扩大付费跑批。

## 改进路线

1. **意图协议**：把投影、日期范围、latest/earliest、计算输入和 group target
   升为生产 IR 一等字段；配套 parser、planner、validator 和回归，而不是让自然语言描述替代执行契约。
2. **结构门禁**：完整 T-BOX 校验路径与字段，阻止 null/未知属性；
   更严格检查每个用到的类是否从 target 可达，以及属性出现在正确语义槽位。
3. **语义计算**：定义按基金分组的期间首末净值、差额/收益率、排序与缺失记录行为；
   基于 schema 保留输入依赖，不要求新增“涨幅”OWL 属性。
4. **语义渲染**：预算内增加关键属性定义/约束，明确记录类不是主题字段的替代品；
   full/slice 采用相同渲染协议，减少格式混杂。
5. **裁判可靠性**：校准先行，错误方向、继承、开世界与含糊输入作为必需控制；
   与确定性规则和专家标注分开报告，不自动根据裁判意见修改本体。
6. **外部题与采样**：新增由独立执行者/专家编写且优化者不可见的题；
   同条件多次真实请求，统计置信区间、模型版本、费用与延迟。

本轮没有扩大到全部 44 题在线测试：裁判校准失败和生产协议缺口已足以
限制解释力，继续扩大题量并不能弥补评价门禁缺陷。

## 复现与审阅

在项目根目录执行，`.env` 沿用现有配置，密钥不通过命令行传入：

```powershell
.venv\Scripts\python.exe tools/tbox_slice_bench.py --output artifacts/benchmarks/tbox-slicing/new-offline.json
.venv\Scripts\python.exe tools/tbox_online_bench.py --output artifacts/benchmarks/tbox-slicing/online-new --current
.venv\Scripts\python.exe tools/tbox_online_bench.py --output artifacts/benchmarks/tbox-slicing/online-new --calibrate
.venv\Scripts\python.exe -m unittest discover -s tests -p test_schema_slicing_dependencies.py -v
.venv\Scripts\python.exe -m unittest discover -s tests -p test_tbox_online_bench.py -v
```

`--ids all` 是完整在线题集选项；本轮未执行。新 output 会产生在线费用。
同 output 的完全相同请求复用缓存，改模型/协议/上下文会重新调用。

文件：

- `artifacts/benchmarks/tbox-slicing/online-pilot-20261008/`：单题协议试运行，不计主对比。
- `artifacts/benchmarks/tbox-slicing/online-v1-20261008/report.json`：最终四路逐题比较。
- 同目录 `report-repaired.json`：中间版本单次自修复实验。
- 同目录 `judge-calibration.json`：5 项已知正误校准。
- 同目录 `cache/`：逐请求 prompt、原文和 token usage，结果目录被 Git 忽略。
- `online-iteration1/2/3-offline.json`、`online-final-offline.json`：各轮冻结集覆盖。

本轮新增离线校验器 7 个测试、领域无关依赖回归 6 个测试。
最终验证数量与工作树审阅入口见主结果文档末尾。
