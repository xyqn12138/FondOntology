## 优化方向与 BKN 对齐

继续保持 TTL 为本体真源，SQLite 为文档证据快照和评测记录载体。遵循参考项目 `E:/LX/bkn-foundry/rules/ARCHITECTURE.md` 与 `bkn-trace/README.md` 的模块职责和执行溯源思路：

- `corpus` 管来源、不可变正文版本、文档和法条定位，不依赖问答或评测模块。
- `qa/rag` 先约束文档、版本与日期范围，再检索和表达；未知或空范围不擅自扩展。
- `evaluation` 独立持有 oracle、参考答案与评分逻辑，gold 不进入被测链路。
- trace 记录实际候选、范围、策略、子片段偏移、HTTP/响应校验事件与缓存命中；已记录的模型分数并非独立重算结果。
- artifact audit 只证明本地结果、trace 与快照的一致性，不证明签名执行真实性、现行法效力或答案的语义正确性。

当前没有足够证据将默认检索替换为更复杂方案。上一轮同预算消融中，BM25、父子 BM25、hybrid RRF、BM25 + rerank 在原 32 题上的门禁通过数分别为 31、30、31、32；随后 18 题中 BM25 和 rerank 都为 18。保留 BM25 默认、rerank 显式可选，父子与 RRF 继续作为实验策略，不引入未经验证的 HyDE 或 rewrite。

三题 DeepSeek Ragas 配对诊断的两组均有 9/9 有效指标，且有相同预算和参考；它只支持对已选样本的诊断。四处 P1 勘误不涉及这三题，因此本轮不额外重跑远程评分。旧失败、超时及完整来源记录保留。

## 下一轮可量化的工作

1. **补齐领域标准与来源覆盖。** 将 P2 建议逐项登记到下一版本；补充权威来源时同时固定原件、发布/施行/修订证据及适用范围。现有四份原件只有固定来源验证，`validity_status=not_checked_current` 不升级。若业务目标是回答现行法，须先补效力与版本证据。
2. **新建真正未曝光的业务集。** 另行冻结不依赖当前输出的题目，覆盖自然业务表述、跨条文、条件不足、版本冲突及应拒答场景；分别统计直接定位、业务咨询和调用契约负控。沿用旧题或改写旧题不能重新获得独立性。正式验收还需要独立领域人员复核。
3. **先分离候选召回与排序错误。** 同时报候选池目标召回、Top-k 目标召回、必需证据组完整率、拒答匹配率、范围违规数和执行错误数，保留全部分母。只有目标在候选池中但未进入 Top-k 时，才优先尝试重排；候选缺失时再比较分词、子片段或语义召回。
4. **冻结单项实验和成本预算。** 固定语料、问题、模型参数、candidate-k、top-k 后进行配对消融；记录逐题增益与退化、查询延迟、完整启动耗时、模型调用和 token 成本。没有留出增益的策略不设为默认。留出集只作一次候选验收，打开失败案例后转为回归集。
5. **补生成层测量。** 当前回答默认是摘录；后续须单独测实际综合回答的任务完成、证据蕴含和无依据断言。Ragas 与确定性检索门禁分别报告，失败/超时不剔除，不把摘录的高 faithfulness 当成用户答案质量。
