## 晚间：intent-real 三失败用例修复（新 API 后）

用户切换新 API（volces ark deepseek-v4-flash）后复跑 intent-real 7/10，三例修复：

1. **R02（规模增长+经理变更的股票基金）**：根因=非流式 LLM 调用读超时。
   关键发现：非流式下服务端生成完成前不下发任何字节，复杂问题推理 145s
   超过读超时；**流式（stream=True）首字节 3.7s 即达，总耗时 145s 正常完成**。
   `_call_deconstructor` 改为流式并抽出共享 `_stream_chat_content`
   （explainer 同改）；失败原因经 `_LAST_LLM_ERROR` 透传到 notes。
   数据缺口（无规模建模/无经理变更）按用户决定只修解析链路，建模另立任务。
2. **R03（医药基金）**：双修复。① 句法语义：filters 支持落在 relation_path
   终点类（`"on": "related"`）——investmentFocus 属于 FundInvestmentStrategy，
   沿 usesInvestmentStrategy 到达；SPARQL 新增 CONTAINS 算子，plain find
   渲染 relation_path 存在性约束。② 数据：gen_sim_abox 把最后一只
   股票型基金确定性覆盖为"生物医药"主题（不动风格池取模分布，只改 1 只基金名，
   001288 云帆生物医药；主题词表原无医药，答案必空）。
3. **R09（货币基金收益怎么样）**：prompt 规则 7/8/9 + few-shot——问收益/表现
   target 是基金类本身（记录类只作 related）；行业主题基金 target=EquityFund。
4. compare 关键词守卫前移到 LLM 之前（两路径一致拒答 Phase 2）。
